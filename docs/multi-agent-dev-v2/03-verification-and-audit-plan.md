# multi-agent-dev V2.0：验证与独立审计计划

状态：开发前验收契约  
适用对象：skills/multi-agent-dev-v2/ 下全部文件、可选 profile 和 Hook  
规则：测试证据绑定固定版本；没有运行的验证必须明确标为未运行。

## 1. 验收层次

1. **文档一致性**：需求、路由表、profile、Hook、降级和测试矩阵使用同一组职责、档位、阶段和版本。
2. **静态/纯函数验证**：route parser、输入规范化、校正/拒绝决策、脱敏与普通工具透传。
3. **配置验证**：Skill frontmatter、openai.yaml、TOML profile 和 hooks.json 结构有效；不把用户未信任/未加载的配置报告为“已生效”。
4. **运行时验证**：在新鲜 Codex 会话中验证所选派发路径、Hook 行为、自定义 profile/显式参数及实际运行元数据。
5. **工作流前向测试**：用典型需求实际加载 V2，检查范围冻结、选人、纠偏、独立审计、拒收回流和终态通知行为。
6. **独立审计**：由未参与对应文件写入的审计责任人对照用户目标、本文档和固定 V2 版本给出结论。

## 3. 运行时探针

运行时探针只在真实 Codex 新鲜会话执行；读取配置、单测、工具列表或模拟 Hook 输入不能替代运行时验证。

### 3.1 Hook 路径探针

对目标工具入口执行最小且无副作用的任务：

1. 启动新会话，记录 Codex 版本和 Hook 配置指纹；如需用户审阅信任，先由用户在 Codex UI 完成。记录官方 Hooks 文档中 Tool coverage 与 PreToolUse 的字段契约、页面核对日期及实际生效的配置来源。
2. 对一个合法职责/阶段输入，使用内置 Agent 且避免自定义 profile 覆盖，故意请求与路由表不同的模型或强度。若 Codex 显示 Hook 结果，记录其事件和 updatedInput；若不显示，不把派发函数输出缺少收据当作 Hook 失败证据，结合非法输入拒绝探针与子会话实际 provenance 判断。
3. 对一个无效 marker 或阶段组合做拒绝探针；确认 Agent 未被创建。
4. 检查普通工具和非 V2 派发仍按预期透传。
5. 把 Hook 结果单独记入 Hook 状态，不因 Hook 改写成功就判定运行路由通过。路由纠正只有在输入故意错误、未有自定义 profile 覆盖且运行元数据显示目标 model/effort 时才算端到端验证。另从已验证的 runtime provenance 来源读取子会话 model 和 reasoning effort；若来源/字段不存在或不可见，记录 ROUTE_UNVERIFIED；若实际值与目标不符，记录 ROUTE_MISMATCH。
6. 不用 Agent 自述、仅有 task name 的工具返回、matcher 配置或 Hook 文件存在作为 Hook/路由通过证据。

Provenance Source Register 至少包含：Codex 版本、派发工具名、读取接口或 UI 步骤、实际字段名、字段代表“请求值”还是“运行值”、证据样例位置、稳定性和覆盖限制。不能把函数参数、Hook updatedInput、子 Agent 自述或非稳定 transcript 推断当成运行值。若只有人工可见 UI 事实，标明核验步骤，且不得伪称为自动化读取。

若 Hook 不能在当前目标入口同步纠正和拒绝，则 Hook 状态记为 HOOK_UNAVAILABLE；仍继续执行 3.2 与 3.3 降级探针。Hook 可以是 HOOK_ENFORCED，同时运行路由仍为 ROUTE_UNVERIFIED 或 ROUTE_MISMATCH。

### 3.2 自定义 Profile 探针

对每个要保留的 profile：

1. 确认 Codex 发现的名称与 profile 内容。
2. 从实际调用入口按名称派发。
3. 读取子会话 runtime model 和 reasoning effort。
4. 修改 profile 或 Codex 版本后重新验证。
5. 在 V1/V2 Hook 共存配置下，确认 profile 派发没有被另一个版本的守卫错误拒绝或重写。

只有实际启动且运行元数据吻合时，profile 才是 PROFILE_VERIFIED。

### 3.3 显式参数探针

当 profile 无法调用时，用当前入口的内置 Agent 明确指定模型与强度参数，执行只读、无副作用工作，核对新子会话实际值。参数被接受但 provenance 不可见时不得标为 EXPLICIT_ROUTE_VERIFIED。

## 4. 前向行为测试任务

至少用以下五种独立任务描述测试完整 Skill，而不是给执行者看预设答案：

1. **精确小改动**：要求在指定位置做单一局部改动，并明确“不得加变量、不得重命名”；验证不会额外启动 think，路由 low 需满足严格准入，审计能逐符号核验。
2. **语义有歧义**：文档和需求对一处行为存在冲突；验证执行前派发只读 think，且未获决定前执行 Agent 不猜测实现。
3. **明确契约的复杂故障**：给出固定复现和边界；验证无需 Sol 设计，执行按 I2 升档，思考强度不扩散到常规审计。
4. **Hook 故意不可用**：通过能力事实关闭 Hook；验证使用已验证 profile/显式路线继续任务，而不是全局停摆，也不声称 Hook 工作。
5. **范围跑偏与证据拒收**：准备含额外变量或未授权行为的候选差异；验证审计拒收并触发授权范围内返工及复审，禁止作者自行签发通过。

任务输入只提供原始需求、项目文件和必要文档。独立评估者不得提前获知预期修正方案；生成物放隔离目录，不污染 V1 或 V2 源文件。

## 5. 独立审计清单

审计员读取需求原文、V2 开发计划、目标文件差异、测试结果及运行证据，并记录：

- 需求和非目标是否无损映射到实现；技能触发范围是否过宽。
- Hook 是否被错误写成前提；fallback 是否有实证条件和明确停止点。
- 是否把 Hook receipt、profile 文件、Agent 自述或工具任务名当成实际模型凭证。
- 三轴分类是否彼此独立；low、xhigh、max 的门槛是否明确且没有无证据升级。
- 思考职责是否保持只读，执行者是否有唯一写入边界，审计者是否独立。
- SubagentStart、PostToolUse、专用派发路径的能力表述是否符合官方当前文档和实际探针。
- 普通工具、普通 Skill、短任务和原有 context-lean/ServerChan 功能是否保持预期。
- 测试是否验证行为与负例；是否记录环境、版本、命令、结果、provenance 和限制。
- 新增文件、变量、工具、依赖、配置和自动化是否都与 V2 目标直接相关。
- 是否存在用户未提交改动覆盖、越界修改 V1 或无授权用户级配置写入。
- V1 保留映射是否具体到来源文件/章节、基线差异、V2 落点和回归场景，而非只写摘要。

每项结论使用“符合 / 不符合 / 证据不足”。出现必需项不符合或证据不足时不得 ACCEPTED；说明具体证据和修正责任，随后复审固定版本。

## 6. 最终放行条件

V2 文档/实现只有全部满足以下条件才可报告完成：

1. V2 独立于 V1，目标文件和配置写入边界清楚。
2. 用户约束、项目文档优先级、范围冻结、纠偏、独立审计和拒收回流完整。
3. 路由矩阵、profiles、Hook 行为、降级模式及支持文档相互一致。
4. 该安装目标至少有一个实测可用的路由路径；未验证的入口明确标注，不能当作默认成功路径。
5. Hook 可用性结论由反事实改写与拒绝探针支持；模型/effort 路由由真实运行 provenance 支持。
6. 前向行为测试至少覆盖本文件第 4 节要求，负例未被隐藏或弱化。
7. 所有必要测试通过；未运行项目、运行错误或无 provenance 的项目明确留作未验证。
8. 独立审计对固定版本无必需的“不符合”或“证据不足”。
9. 用户收到修改清单、验证命令/结果、Hook/Profile/Explicit 路由能力状态、通知状态及剩余限制。

效率评价是后续观察项，不是首轮 V2 技术放行门槛；样本不足时可以交付，但不得声称效率目标已实现。若后续要比较 V1/V2，应先冻结 V1 基准版本和可重复任务集；V1 工作区有未提交差异时不得把它含混地当作基准。使用配对任务，并尽量保持任务输入、Codex 版本、工具入口和环境一致；报告样本数、原始差异及计量口径，包括 Token、耗时、返工回合数、审计拒收数、范围/约束违规数和测试缺陷。不得用 Token 或返工改善抵销质量指标退化；若样本或条件不足，只报告观察结果和限制，不下“稳定改善”或普遍优于 V1 的结论。

## 7. 验证证据格式

每项证据最少记录：

| 字段 | 内容 |
| --- | --- |
| Evidence ID | 稳定编号，如 ROUTE-01-E1 |
| 对应条件 | 本文测试 ID 或用户硬约束 ID |
| 固定版本 | V2 commit/diff ID/文件哈希 |
| 环境 | Codex 版本、操作系统、派发工具入口、Hook trust 状态 |
| 操作 | 真实命令或可复现 UI 步骤 |
| 预期与实测 | 结果、退出码、实际模型/effort 或不可见说明 |
| 限制 | 覆盖范围、未观察到的事实、不能推出的结论 |
| 结论 | 符合 / 不符合 / 证据不足 |

证据不得包含 SendKey、Token、完整 prompt、敏感路径或未脱敏 Provider 内容。
